# Product

## Register

product

## Users

- Developers who found one of Khang's tools (from GitHub, npm or a post) and want to install it and get a first result quickly.
- Coding agents (Claude Code, Codex and others) that a developer points at a tool's docs. Most of these tools are built for agents, so the agent is often the main reader.
- Khang, who maintains five or more tools and wants their docs current without asking for it.

## Product Purpose

One place on khangle.dev where every tool's docs live, kept in sync with each tool's repo automatically. Success: a developer installs a tool from its page in a minute, an agent loads a whole tool from one llms-full.txt URL, and no page lags a release by more than an hour.

## Brand Personality

Quiet, exact, friendly. Plain sentences for people on the surface; exhaustive, literal detail for agents in the agent pages and llms files.

## Anti-references

- Marketing landing pages with logos walls, testimonials and invented metrics.
- Docs sites whose content drifts from the code because it lives in a second place.
- Heavy theming that slows reading: gradients behind text, glyph icons, decorative badges.

## Design Principles

1. The repo is the source of truth; the site never holds its own copy of a tool's docs.
2. Every page has a human view and a plain-text twin.
3. Show provenance: which version and commit a page came from.
4. A broken library degrades to its last good pages, never to an empty site.

## Accessibility & Inclusion

WCAG AA contrast on the light theme, keyboard search (Cmd/Ctrl K), 44 px tap targets on phones.
